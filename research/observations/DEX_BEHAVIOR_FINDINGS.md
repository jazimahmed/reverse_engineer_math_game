# DEX behavior findings

Artifact: `research/apk/Math-Games-v14-2-[Premium]-modyolo.apk`  
Evidence source: `research/observations/classes_dump.txt`, generated by Android SDK `dexdump.exe -d` from the APK's `classes.dex`.  
Confidence describes the code-level finding, not runtime visibility. The app has not been launched.

## DEX-RN-001 — Random-number level loading

- Confidence: CONFIRMED (static code path).
- `RandomGameActivity.readJSONData()` loads the random-number asset via `RnJson.readJSONFromAsset()`, then Gson parses its `levels` into `randomGameLevels`.
- `startGame()` indexes the level list with `MyConstant.LEVEL_POS`, reads the selected level's numbers, target (`randomNo`) and `maxHints`, and initializes the level UI.
- `gameOver()` marks `isLevelCompleted`, advances the saved random-game level to `LEVEL_POS + 1` only when that exceeds the currently saved value, then opens `Result_Game2Activity` with `KEY_ACTIVITY=RANDOM_NUMBER`.
- Limit: the invocation conditions for `gameOver`, how failed equations are communicated, and actual reachable navigation remain unverified.

## DEX-RN-002 — Arithmetic evaluator

- Confidence: CONFIRMED (static implementation).
- `calResult(String[])` reads integer operands from indexes 0 and 2 and the operator from index 1.
- Supported symbols are `+`, `-`, `×`, `÷`.
- Addition, subtraction and multiplication use integer operations. Division returns integer quotient only when the divisor is nonzero and left operand is greater than or equal to the right operand; otherwise returns 0. No divisibility requirement appears in this method.
- Unknown operator, parsing/array exception, or division guard failure returns 0.
- This is an internal evaluator rule, not proof that every returned zero is treated as an incorrect player action.

## DEX-RN-003 — Equation interaction

- Confidence: CONFIRMED (static control logic, partial).
- `showEquationTwo(String)` returns false immediately once `isLevelCompleted` is true. It calls `checkInput` while iterating the three temporary equation slots. Valid selections are placed into the temporary equation and the UI is updated. `completeEqTwo(int)` compares the supplied value to `randomNo`; a mismatch calls `gameOver()`.
- When results exist, `completeEqTwo` plays feedback and triggers a toast/animation once result count equals `max`; otherwise it advances equation tracking and re-enables operator selection while disabling number selection.
- Limit: full action semantics and the “max” completion relationship require further method-flow inspection and runtime confirmation. Do not infer scoring or a wrong-answer penalty from these methods alone.

## DEX-MP-001 — Timed math-pieces candidate

- Confidence: CONFIRMED (static identifiers and code), UNKNOWN (player-visible rules).
- `mathpiecesData.json` contains 150 `timerGameLevels` records with cells, unlock and stars fields. `Game_MathPieces_Activity` has methods named `setTimeToString`, `calculateResult`, `loadData`, hint, and grid display methods. `calculateResult` computes a percentage from two integer fields when the first is nonzero.
- The class shape and dataset suggest a timed grid puzzle, but exact objective, scoring, level unlock, and whether/how it is exposed in menus remain unknown.

They reproduce isolated DEX methods only; there is no screen or complete mode yet. All runtime behavior remains pending an emulator/device session.

## DEX-MULTI-001 — Multiplayer room question generation

- Confidence: CONFIRMED (static DEX implementation); UNKNOWN (runtime entry/reachability and presentation).
- `MultiplayerActivity.CreateNewRoom()` constructs `GenQuestions(24)`, asks it for the full question list, then passes that list to a `Room` constructor with one boolean false and integers 0 and 30. This is code path evidence only; backend persistence and user-visible behavior are not established by this call alone.
- `GenQuestions.getAllQusetions()` creates `count` records with sequential IDs and stores two operand strings, an operator string, and an integer answer.
- Each question index uses an index-specific set of half-open operand/operation ranges. `getrandomNum(high, low)` computes `Random.nextInt(high-low)+low`, so values include `low` and exclude `high`.
- Operations are `+`, `-`, or `x`. Subtraction operands are swapped when needed to keep the difference nonnegative. Multiplication uses lowercase `x` for its stored operator.
- Exact pattern table and supporting DEX lines are recorded in `research/GAME_RULES.md` and implemented in `src/domain/multiplayerQuestions.ts`.
- Limitation: this generator is not evidence for the single-player random-number mode and does not specify answer timing, scoring, matchmaking, network failure handling, or multiplayer rules.

## DEX-RN-004 — Input category validation

- Confidence: CONFIRMED (static method logic).
- `checkInput(String, int)` recognizes the operator strings `+`, `-`, `×`, and `÷`. For slot index 1 it accepts those operators and rejects other strings; for all other indexes it rejects the operator symbols and accepts non-operator strings.
- It does not itself validate that a non-operator string is a legal integer. The enclosing UI flow supplies its available tile values.
- The TypeScript helper reproduces this category check; whitespace/empty or malformed non-operator strings may pass this helper, as they can through this method, and are handled later by integer parsing.

## Java integer parsing parity

`calResult` calls `Integer.parseInt` and catches parsing exceptions. The independent helper models ASCII signed 32-bit decimal strings, rejecting whitespace, decimal notation, and out-of-range values. APK dataset operands are ASCII numbers. Runtime-generated keyboard inputs have not been observed, so Unicode digit parsing parity is not claimed.

## DEX-RN-009 - Equation selection and target branch

- Confidence: CONFIRMED (static control-flow semantics); player-facing success/failure meaning UNKNOWN.
- `showEquationTwo(String)` returns immediately once `isLevelCompleted` is true. Otherwise it searches its three input slots, calls `checkInput(value, slotIndex)`, and accepts the value only when it matches that slot's operator-vs-number category. Accepted values are written into the temporary input array and the current equation-row views.
- After accepted slot index 0, the activity enables operator controls and disables number controls. After accepted slot index 1 or 2, that branch enables number controls and disables operator controls. Initial setup also enables numbers and disables operators; a target-match transition with more rows then sets the next row up for operator selection.
- When the three-slot equation is evaluated, `calResult` is appended to `results`. The activity updates the equation row with the latest prior result and can proceed to another configured row.
- `completeEqTwo(value)` calls `gameOver()` when `value != randomNo`. The `gameOver()` method marks `isLevelCompleted`, updates the saved highest unlocked level if needed, and starts `Result_Game2Activity` with `KEY_ACTIVITY=RANDOM_NUMBER`.
- When the value equals `randomNo`, `completeEqTwo` does not take that result transition. If the accumulated result count is below `max`, it seeds the next row from the latest result and alternates input controls. At the `results.size == max` branch it plays a sound, invokes `CustomToast()`, animates the undo control, and returns.
- The app's user-facing interpretation of target match/mismatch, the toast text, whether each result row is an attempt or a chained step, and all result-screen buttons remain UNKNOWN. In particular, the static `gameOver()` name and its level-unlock write do not establish whether a mismatch is displayed as a win or loss.
- `showEquationTwo` has exception handlers that call `onBackPressed()`; malformed view/state behavior is therefore not fully recoverable from the nominal path alone.

## DEX-MP-002 - Math Pieces completion star calculation

- Confidence: CONFIRMED for the static DEX calculation and call path; runtime semantics UNKNOWN.
- `Game_MathPieces_Activity.calculateResult()` returns 0 immediately when its `correctAttempts` field is zero. Otherwise it computes `correctAttempts / (correctAttempts + wrongAttempts) * 100` as a float. It returns 2 for an inclusive 40–90% range, 3 for greater than 90% through 100%, and 1 for other percentages.
- `onGameComplete()` calls this method, stores the returned star count on the current `PiecesGameLevel` when present, then calls `gameOver()`.
- Evidence: DEX methods around `classes_dump.txt` lines 922092–922153 and 921169–921185. Independent helper: `src/domain/mathPieces.ts`.
- Limits: UI meaning/visualization of star tiers, attempt-counter event timing, level-completion conditions, persistence, timer behavior, and runtime reachability remain unknown. The helper is documented for nonnegative attempt counts; ordinary gameplay bounds are not runtime-confirmed.

## DEX-MP-003 - Math Pieces line equation check

- Confidence: CONFIRMED for the DEX validation procedure; INFERRED for the player-facing objective; runtime interaction UNKNOWN.
- `checkCorrectEquation()` gathers `PieceEquation` objects returned by both `getEquationByRows()` and `getEquationByColumn()`, then checks each line using `checkEquations(PieceEquation)`.
- The line checker reads five cell strings. At interior positions it recognizes `+`, `-`, `×`, or `÷`, requires adjacent operands not to be one of the operator/equality symbols, parses them as integers, and computes a result. Addition and multiplication use integer arithmetic; subtraction selects the nonnegative absolute difference; division uses integer division. For each operation, the int result is converted to float and passed to `Math.round()` before becoming a string, which can change very large integer results through float precision. The code searches the line for that result at either endpoint immediately beside `=`.
- The inferred objective is to arrange number/operator/equality pieces so every row and column forms a matching arithmetic equality. This is supported by code, but player-facing instructions and actual input flow remain unobserved.
- Independent helper: `isMathPiecesEquationCorrect()` in `src/domain/mathPieces.ts` models a complete, well-formed five-cell line, including Java int overflow and float-rounding parity. It returns false for malformed lines; the original may throw during parse, and division by zero throws in the source path.
- Limits: does not establish tile dragging/undo mechanics, when rows are checked, animation/feedback, exact error recovery, timer behavior, or how a player can reach the activity.

## DEX-MP-006 - Math Pieces drop-triggered check pass and attempt counters

- Confidence: CONFIRMED for the static chain and counter semantics; runtime reachability UNKNOWN.
- Drop → check: an accepted drop posts `MyDragListener$2` immediately; it performs the transfer branch, restores the source view and schedules `MyDragListener$2$1` 100 ms later. Both `MyDragListener$1` (scheduled after 100 ms on another drop branch) and `MyDragListener$2$1` call `clearHintAnimation()`/static `x()` → `checkCorrectEquation()`. `setTextOnCells()` separately schedules an unrelated 200 ms board-clear runnable (`Game_MathPieces_Activity$4`).
- Check pass: `checkCorrectEquation()` rebuilds all row/column `PieceEquation` objects fresh (`isCorrect=false`), resets `score` to 0, valid lines become `setCorrect(true)` + styling + `score++`; completion calls `onGameComplete()` only in the pass where `score` equals the master `equations` list (rows + columns, cleared and repopulated by `loadData()` via `reset()`/`setTextOnCells()`). - Counters: `calculateResult()`'s debug logs name `field@74c2` as correctAttempts (`o`) and `field@74c3` as wrongAttempts (`p`). correctAttempts never changes except `+equations.size()` on a completing pass. wrongAttempts increments only in `checkEquations()` failure branches, de-duplicated per container tag in `equtaionTags` (`field@74a2`). - Timer: `time`, `totalMiliseconds`, `totalseconds`, `secVar`, `resumeVal` and `fixedTimeInMS` fields exist but the dump has no nonzero write; the timer's effect on the mode remains UNKNOWN.
- Evidence: `classes_dump.txt` lines 918427–919006 (runnables), 919598–919694 (`checkCorrectEquation`), 919955–919988 (deduped wrong-attempt sites), 921357–921401 (`reset`), 921510–921882 (`setTextOnCells`), 922100–922149 (`calculateResult` logs), and E-APK-020.
